# AGENTS.md

Arkanum is an opinionated code-server container: a Docker image, a helper CLI (`arkanum`), and a docs site — three ecosystems in one repo.

The canonical forge is self-hosted Gitea (`gitea.ocram85.com/arkanum/arkanum`); GitHub/Codeberg are mirrors. Open issues/PRs on Gitea only. CI is Woodpecker (`.woodpecker/*.yml`, `ci.ocram85.com`) — there are no GitHub Actions here.

## Structure

- **Go CLI**: `cmd/cli/` + `internal/*` (module `gitea.ocram85.com/arkanum/arkanum`, single dep `urfave/cli/v3`). Branch `add/arkanum-go` ports the legacy bash helper at root `./arkanum` to Go; the bash script stays as the reference implementation until the port lands. This branch's `Dockerfile` installs the compiled binary (`ADD dist/arkanum`); master still installs the bash script. CLI version is hardcoded in `cmd/cli/main.go` (independent of `package.json`).
- **Container image**: `Dockerfile` on `quay.io/linuxserver.io/code-server`. `code-server/` holds branding assets and the s6 `svc-code-server/run` override; `FiraCode/`, `starship.toml`, `gitconfig-system` are copied into the image at the exact paths in the Dockerfile.
- **Docs**: `docs/` (VitePress) with root `package.json` + `bun.lockb`. `package.json` is named `arkanum-docs` and is docs-only tooling, not an app manifest.

## Commands

- `just build-cli` → `dist/arkanum` (CGO_ENABLED=0, linux/amd64, `-s -w`). This is the blessed build used by CI and consumed by the Dockerfile. `make build` writes `dist/arkanum-cli`, which nothing consumes — prefer `just`.
- Docker image builds expect `dist/arkanum` to already exist in the build context (CI's `cli` step runs `just build-cli` before the buildx step).
- Go verification: `go vet ./...` and `gofmt -w` on touched files. Several committed Go files are not gofmt-clean and CI does not check gofmt.
- There are no Go tests yet; `go test ./...` passing is meaningless.
- Docs: `bun install`, then `bun run docs:dev` (VitePress, cleans dist, serves on port 1313) / `docs:build` / `docs:preview`.
- CI lints `editorconfig` + prettier (via peckify): 2-space indent for everything except tabs in `*.go`, `Makefile`, `Caddyfile`.

## CLI runtime assumptions

Installers only fully work inside the Ubuntu-based arkanum container: they shell out to `apt-get` via `sudo -E`, append to `/etc/bash.bashrc`, and use `/config` + `$HOME` paths (`~/enable_motd`, `~/arkanum-session`). On a dev machine you can only verify `--help`/command wiring and `arkanum completion bash`. VS Code user settings are embedded from `internal/config/default-settings.json` via `go:embed` — edit that file, not a copy.

## Commits, PRs, releases

- Conventional commits, enforced by commitlint. Allowed types: `feat, extend, fix, chore, style, refactor, test, perf, ci, WIP`. A lowercase scope is **required** (`fix(installer): ...`), type should be lowercase too.
- PRs target `master` (squash-merged, shown as `(#N)` in history). Renovate pins all versions, including Docker tags and plugin images inside `.woodpecker/*.yml` — let Renovate own those bumps, don't hand-edit versions.
- Releases are automated by the `ready-release-go` Woodpecker plugin (`.woodpecker/release-helper.yml`; it maintains a `next-release/master` branch). Version bump comes from PR labels per `release-config.ts`. `CHANGELOG.md` is generated by the Gitea changelog tool (config `.changelog.yml`, helper VS Code task "Update GiteaChangelog") — do not hand-edit it.
- PR builds publish container tag `next`; `latest` follows the default branch.
